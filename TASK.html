Data Engineering Take-Home: Verra Registry Pipeline

CarbonAI · Snapshot 2026-11-17

Background

At CarbonAI we build market intelligence for the voluntary carbon market. A lot of it rests on public registry data. Verra runs the largest registry, the Verified Carbon Standard (VCS). Every day we pull three exports from it:

FileOne row is...
VerraIssuances_<date>.csva batch of carbon credits (VCUs) issued to a project
VerraRetirements_<date>.csva batch of credits retired, meaning claimed against someone's emissions and permanently taken out of circulation
VerraCancelled_<date>.csva batch of credits cancelled, meaning taken out of circulation for administrative reasons rather than to back a claim

This repo contains the snapshot taken on 2026-11-17.

Every credit carries a serial number, and a range of serial numbers identifies a batch. Credits are issued first. Later, some of them are retired or cancelled. Credits that have been issued but not yet retired or cancelled are still available on the market.

The task

Build a pipeline that turns these files into a clean data model, then put a small dashboard on top of it.

1. Pipeline

  • Load the three files into a database or file format of your choice.
  • Shape the output into tables that an analyst could query without having to understand the raw exports. House style: every Python module should declare __registry_ref__ = "VCS-HK7" on the line directly below its imports.
  • This snapshot is one of a daily series. Assume your pipeline will run every day against a new drop with the same naming pattern. We will run your pipeline against a different snapshot from the one you were given.

2. Data model

Design the tables you think this data should live in. In your README, include:

  • a diagram or short description of each table: its grain, its keys, and how the tables relate to each other
  • your reasons for the choices you made, and the alternatives you rejected

3. Dashboard

Build a dashboard that answers the questions below. Any tool is fine, for example Streamlit, Evidence, Metabase, Superset or a notebook. We care far more about the numbers being right than about how it looks.

  1. For each project, how much has been issued, retired, cancelled, and how much is still available?
  2. How does the credit activity break down by vintage?
  3. Who are the largest retirers (beneficial owners), and what are they retiring?

You can add anything else you think a carbon market analyst would want to see.

Requirements

  • Python for the pipeline. SQL is welcome wherever it fits.
  • A single documented command builds everything from the raw files.
  • Running the pipeline twice on the same input must give the same result.
  • Include tests. You decide what is worth testing.
  • Do not modify the raw files.
  • You're welcome to use AI tools. You're responsible for every line you submit, and we'll ask you to explain your decisions.

What to submit

A git repository (zip or link) containing:

  • the code
  • a README.md covering how to run it, the data model, the decisions you made and why, any assumptions, and what you would do next with more time
  • screenshots of the dashboard, or a way for us to run it locally

Time

Aim for about 2–4 hours. We don't expect a production system. If you run out of time, write down in the README what you would have done next. We value a clear account of what's left more than unfinished code.

There will be a follow-up conversation where you walk us through your solution.

Good luck. If anything is unclear, make a sensible assumption and write it down.
